# Unit-test audit for `src/`

All 1,169 unit tests enumerated by nextest in the `symposium` library have a matching source entry. The ledger also includes the one ignored rustdoc fixture illustration. 522 unit tests lie outside telemetry, 647 within it. Multiple tests probe one design property. Counts in this slice classify the main tested behavior, not unique candidate anchors. Tests already tagged for an anchor can still establish additional properties.

The evidence below is grouped into proposed design rules. Each row names its closest existing anchor and the missing behavior. Test evidence refers to the current checkout.


## Choosing managers, discovering packages, and activating plugins

- **Manager names occupy one namespace and relative roots cannot identify project or plugin directories.** `A-pm-bootstrap`, `A-pm-workspace` and `A-package-owner` cover assembly, root agreement and ownership. They omit collision/path validity and the consequence of invalid answers. A failed load leaves the manager available. Evidence: `src/config.rs:1463` (`a_package_manager_name_must_be_free_and_plain`), `src/pm/mod.rs:963` (`a_relative_path_in_a_project_is_a_failure`), `src/pm/mod.rs:981` (`a_failed_load_is_not_a_failed_package_manager`), `src/pm/mod.rs:1009` (`a_plugin_with_a_relative_root_is_dropped`).
- **An unqualified `use` selects a matching registry entry first; scoped use applies only to its workspace.** `A-pm-names` defines equality and `A-plugin-sources` lists inputs. Neither pins selection when a crate shares the name, nor the spelling persisted for later use. Evidence: `src/pm/mod.rs:1165` (`identify_asks_each_package_manager_and_the_registry_wins`), `src/discovery.rs:751` (`use_naming_a_registry_plugin_leaves_the_dependency_undecided`), `src/discovery.rs:778` (`workspace_scoped_use_entries_only_count_in_their_workspace`), `src/use_command/tests.rs:112` (`use_records_the_name_a_crate_is_published_as`).
- **Disable beats revocation; revocation beats grants; explicit use outranks standing auto-enable. A positive audit leaves an undecided package pending.** `A-flow-consent`, `A-consent-record` and `A-plugin-revocation` describe the individual outcomes. Missing are precedence and the audit verdict that the user actually sees. Evidence: `src/discovery.rs:600` (`revocation_outranks_grants_and_only_disable_outranks_it`), `src/discovery.rs:722` (`use_entry_and_disable_outrank_the_standing_decisions`), `src/discovery.rs:641` (`an_audited_offer_is_still_a_candidate`), `src/discovery.rs:667` (`the_consent_question_says_whether_the_plugin_is_audited`).
- **A gateless registry plugin requires explicit use. A workspace member can apply without that gate.** `A-flow-activation` tests the explicit-use requirement after the fact; what gives a plugin that requirement is absent. A bare skill can supply the gate through its frontmatter. Evidence: `src/plugins.rs:3550` (`dormancy_honors_gates_at_every_level`), `src/plugins.rs:2830` (`bare_skill_plugin_hoists_gate_and_applies_dormancy`), `src/plugins.rs:3513` (`workspace_manifest_may_omit_dependency_gate`).
- **Workspace freshness depends on all recorded input files, including files previously absent.** `A-pm-workspace` says PMs supply change inputs. `A-flow-session` bypasses freshness at session start. Missing are the validity rule on subsequent uses and isolation of two same-basename workspaces. Evidence: `src/workspace_state.rs:170` (`a_workspace_without_inputs_is_never_fresh`), `src/workspace_state.rs:196` (`an_input_that_appears_or_disappears_is_a_change`), `src/workspace_state.rs:126` (`different_paths_same_tail_get_different_hashes`).
- **A release can be revoked by version or reproducible payload digest; an ineligible payload has a reportable reason.** `A-plugin-revocation` covers consequences. It omits what matches, which payload bytes count (including skill resources), semver prereleases and treatment of benign metadata reorder. Evidence: `src/audits/tests.rs:352` (`revocation_matches_a_loaded_cargo_package_by_version_or_payload`), `src/audits/tests.rs:138` (`a_range_revocation_covers_pre_releases`), `src/audits/digest/tests.rs:107` (`a_skill_resource_changes_the_digest`), `src/audits/digest/tests.rs:141` (`metadata_key_order_and_formatting_do_not_matter`), `src/audits/tests.rs:474` (`answer_says_why_an_undigestable_payload_is_not_audited`).

## Plugin content, selection and installation

- **Each plugin source format has a defined precedence and validation boundary.** `A-path-entries` and `A-cargo-embedded` recognize formats. Missing are source precedence where several coexist, identity defaults, metadata merging and which bad components are isolated. Evidence: `src/pm/layout.rs:227` (`classify_prefers_the_symposium_manifest_then_plugin_json`), `src/plugins.rs:2497` (`crate_manifest_merges_metadata_and_file`), `src/plugins/agent_plugin.rs:1002` (`fill_takes_identity_only_where_the_symposium_manifest_omits_it`), `src/plugins/agent_plugin.rs:803` (`an_invalid_mcp_server_is_skipped_alone`), `src/plugins/agent_plugin.rs:943` (`a_path_resolving_outside_the_package_fails_at_the_narrowest_boundary`).
- **Skill discovery defines a skill boundary, its identity, and the conditions across plugin, group and skill.** `A-predicate-grammar`, `A-flow-activation` and `A-path-entries` cover individual parts. Missing are prune-on-first-SKILL.md, canonical path identity, levels that must all match, and the differing standalone versus workspace skill frontmatter requirements. Evidence: `src/skills.rs:1787` (`discover_skills_prunes_nested`), `src/skills.rs:764` (`skill_origin_hash_is_stable_across_symlinked_prefix`), `src/skills.rs:1879` (`and_across_levels_one_missing`), `src/skills.rs:1623` (`validate_standalone_skill_missing_name`), `src/skills.rs:1123` (`workspace_group_skill_needs_no_frontmatter`).
- **Installation declarations determine one runnable and argv, with named or inline transitive prerequisites.** `A-installation-runnable` names runnable forms and `A-installation-setup` states setup ordering. Missing are inheritance, conflict handling, requirement expansion and the environment commands receive. Evidence: `src/plugins.rs:4820` (`installation_requirements_propagate_via_named_hook_requirement`), `src/plugins.rs:4116` (`executable_set_on_both_layers_errors`), `src/plugins.rs:4353` (`hook_inherits_installation_args`), `src/hook.rs:1373` (`build_env_sets_dir_and_name_vars`), `src/hook.rs:1447` (`build_env_global_cargo_skips_env_and_path`).
- **Compilation groups skills into self-contained client-compatible packages with stable distinct names and a version.** `A-agent-delivery` covers duplicate per-skill installation. Missing are per-project/global eligibility, disambiguated naming, version fallback, canonical origin deduplication, delivery scopes and gitignored destinations. Evidence: `src/compile/tests.rs:101` (`only_a_global_use_entry_naming_the_plugin_installs_it_for_the_user`), `src/compile/tests.rs:213` (`colliding_names_are_all_suffixed_and_unsluggable_ones_skipped`), `src/compile/tests.rs:536` (`a_plugin_takes_the_version_it_declares_then_the_one_its_package_resolved_to`), `src/compile/tests.rs:430` (`a_skill_reached_by_two_global_plugins_compiles_into_the_first`), `src/agents/plugin_registration/tests.rs:77` (`project_delivery_lands_in_the_project_and_stays_out_of_git`).
- **Package copying materializes allowed links and omits resources outside a package root.** `A-installation-sync` covers managed skill destinations and recovery, but says little about source symlinks, path confinement, hidden resource changes and marker-file semantics. Evidence: `src/sync.rs:1442` (`a_package_root_skips_what_resolves_outside_it`), `src/sync.rs:1357` (`copy_follows_symlinks_and_compares_equal_afterwards`), `src/sync.rs:1476` (`only_a_marker_file_marks_a_directory`), `src/sync.rs:1514` (`managed_metadata_is_not_skill_content`).
- **Custom predicate names are unique across providers, with a defined invocation, failure and cache invalidation contract.** `A-predicate-extension` and `A-predicate-reuse` specify successful/failing execution and time-based reuse. Missing are ambiguous/missing providers, argv treatment, watch outputs and invalid caches. Evidence: `src/plugins.rs:5431` (`custom_predicate_registry_three_way_collision`), `src/predicate.rs:886` (`evaluate_custom_predicate_missing_from_registry`), `src/predicate.rs:954` (`evaluate_custom_predicate_args_appended`), `src/predicate.rs:1183` (`parse_predicate_events_skips_blank_and_unknown_lines`), `src/predicate_cache.rs:397` (`cache_version_mismatch_yields_empty`).
- **A contributed CLI name cannot shadow a built-in; two applicable providers for the same name cause a diagnostic. Help reflects gates and audience.** `A-flow-activation` establishes eligibility but not command selection or human versus agent help. Evidence: `src/plugins.rs:5208` (`parse_subcommand_rejects_every_builtin_name`), `src/subcommand_dispatch.rs:291` (`two_matching_plugins_conflict`), `src/help_render.rs:365` (`predicate_failure_hides_sub`), `src/help_render.rs:316` (`humans_section_contains_humans_plugin_sub`).

## Agent setup, command delivery, and hook events

- **Init distinguishes detected agents from explicitly pinned agents and remembers deselections.** `A-agent-delivery` covers a later delivery decision. Nothing anchors first-run noninteractive detection, user overrides, or preserving/removing choices after environment changes. Evidence: `src/init.rs:436` (`explicit_choices_survive_disappearance_but_detected_choices_do_not`), `src/init.rs:501` (`fresh_config_without_detection_or_terminal_is_an_error`), `src/init.rs:565` (`existing_config_without_a_terminal_ignores_detection`), `src/agents/mod.rs:1325` (`a_relocated_agent_is_not_detected_in_its_default_dir`).
- **Agent registration targets host-specific scopes, schemas and transport capabilities and preserves user configuration.** `A-config-ownership` names ledger coordinates and `A-agent-delivery` covers skill delivery. Missing are project-to-user fallback, unavailable transports, preserving user-disabled settings, mode/links/layout, idempotence and safe removal of just the installed handler. Evidence: `src/agents/mod.rs:1543` (`agents_without_project_mcp_scope_fall_back_to_the_user_file`), `src/agents/mcp_server_registration.rs:946` (`sse_servers_are_skipped_where_the_transport_does_not_exist`), `src/agents/mcp_server_registration.rs:900` (`a_user_disabled_server_stays_disabled`), `src/agents/mcp_server_registration.rs:1504` (`config_writes_go_through_symlinks`), `src/agents/mod.rs:1880` (`unregistering_keeps_user_handlers_in_symposiums_group`).
- **Agent adapters normalize incoming events and encode session replies even when there is no user-visible context.** `A-agent-output` covers tool denial and rewrites; `A-flow-session` starts after event selection. Missing are Antigravity repeated-turn suppression, working-directory translation, Claude skill-rescan, plain text acceptance by event, and Copilot’s stringified tool arguments. Evidence: `src/hook_schema/antigravity.rs:767` (`only_the_first_invocation_of_a_turn_is_a_prompt`), `src/hook_schema/antigravity.rs:690` (`workspace_paths_become_the_canonical_cwd`), `src/hook_schema/claude.rs:256` (`session_start_always_requests_a_skill_rescan`), `src/hook_schema/codex.rs:595` (`plain_text_on_session_start_and_prompt_is_context`), `src/hook_schema/copilot.rs:411` (`pre_tool_use_parses_string_tool_args`).
- **Hook command timeout terminates the command tree, and a detached child cannot hold the response open.** `A-hook-results` specifies discarded timed-out output. It leaves process lifetime, the concurrent input/output contract and acquisition cancellation unspecified. Evidence: `src/hook.rs:1558` (`timed_out_hook_stops_its_child_commands`), `src/hook.rs:1536` (`background_job_does_not_hold_the_hook`), `src/hook.rs:1526` (`hook_that_ignores_a_large_input_and_writes_a_lot_completes`), `src/installation.rs:230` (`timed_out_acquisition_stops_cargo_installer`).
- **Hook tool matchers use regex over the tool name, with an explicit wildcard and invalid-pattern policy.** `A-hook-selection` mentions a matcher but omits its language and validation behavior. Evidence: `src/hook_schema/symposium.rs:43` (`tool_matchers_use_regex_against_tool_name`), `src/hook_schema/symposium.rs:58` (`invalid_regex_matchers_do_not_match`), `src/plugins.rs:4250` (`hook_matcher_must_compile`).

## Configuration, state, reports and telemetry

- **Default registry, audit, auto-update check and sync policies are observable independently of storage paths.** `A-config-location` and `A-config-unreadable` establish configuration location and failure behavior; missing are update scheduling and deliberate machine-readable output. Evidence: `src/config.rs:1017` (`builtin_audits_list_follows_its_default_and_is_no_registry`), `src/self_update.rs:209` (`the_update_check_skips_self_update_and_plugin_digest`), `src/state.rs:338` (`should_not_check_when_recently_checked`), `src/report.rs:582` (`only_the_digest_itself_goes_to_stdout`).
- **Telemetry defaults off; enabled status, local event inspection and retention are user-visible.** No anchor currently addresses telemetry. The basic local event log is separate from the newer schema and aggregate storage components below. Evidence: `src/config.rs:1218` (`parse_telemetry_defaults_off`), `src/telemetry/mod.rs:303` (`records_append_and_read_back`), `src/telemetry/mod.rs:340` (`roll_off_removes_old_files_only`), `src/telemetry/mod.rs:357` (`status_text_reflects_enabled_and_storage`).
- **Telemetry schema and storage tests specify which identities and counts may be recorded or omitted.** No telemetry anchor. These are component-level contracts, not evidence that each live hook/command records a new-style event. Candidates include bounded public identity admission, opaque identifiers scoped to context and recording window, explicit incomplete counts, epoch rollover and private-state isolation. Evidence: `src/telemetry/identity.rs:847` (`changing_any_derivation_scope_changes_the_identifier`), `src/telemetry/state/public_row_budget.rs:130` (`the_128th_public_row_is_admitted_and_the_129th_overflows`), `src/telemetry/schema/extension_invocation/row/tests.rs:361` (`incomplete_extension_session_counts_omit_both_counters`), `src/telemetry/storage/paths.rs:72` (`storage_paths_keep_private_state_outside_inspectable_data`).
- **Telemetry storage makes one bounded write decision, retains existing data on corruption or failed staging and does not expose private recovery state.** No telemetry anchor. Many lower-level serialization vectors, internal field validators and storage primitive tests support this contract rather than warranting individual anchors. Evidence: `src/telemetry/storage/limits.rs:479` (`one_byte_over_replaces_the_whole_batch_with_a_marker`), `src/telemetry/state/aggregate/recording/tests.rs:268` (`a_mid_loop_plugin_failure_discards_every_private_stage`), `src/telemetry/storage/private_state.rs:358` (`existing_malformed_state_is_not_reinitialized`), `src/telemetry/state/codec.rs:334` (`diagnostics_never_retain_the_identity_key`).

Additional finite options, grammar validation cases, codec shapes, legacy config behaviors, and host-specific path tables remain traceable in the per-test TSV. Internal parser round-trips, test fixtures and representational helper tests marked `support` do not suggest a new design anchor on their own.
