# Evaluation crate and repository scenarios

Audited 666 source tests in `symposium-eval` plus the two out-of-workspace hidden Rust checks in `evals/tasks`. `cargo nextest list -p symposium-eval --message-format json` enumerated 661 on this Linux checkout, including 32 ignored tests. The remaining five source tests are platform-gated counterparts. There are no runnable Rust documentation examples in these directories. The five snapshot assertions expand inside ordinary named tests. Quoted `#[test]` examples used as grader inputs were counted under their enclosing tests. The ledger contains 668 entries: 3 gap, 8 partial, 1 covered, and 656 evaluation or fixture support. The audit inspected assertions, including ignored real-sandbox scenarios.

**Tooling-only behavior:** The trial driver, isolated staging, transcript parsing, result schema, grading, and ownership/evidence readers implement the RFD under `md/rfds/skill-evaluation`. A checker that rejects normalized bundle-name collisions does not establish that the runtime rejects those plugins; the real compiler fixtures in fact observe both eligible skills. Parsing synthetic `SessionStart` trace lines or fabricated skill directories does not verify that a real agent actually wrote/read them. The one covered shared predicate parser case is `symposium-eval/src/skill_md.rs:231` against `A-predicate-grammar`.

**Repository scenarios:** `evals/tasks/formatting/task.toml` expects the `rust-formatting` skill and `format-on-stop` hook and uses a format check; `evals/tasks/store-durability/task.toml` expects the `fixture-store` skill. Their hidden Rust checks (`doubles` and `settings_survive_reopen`) check the submitted task code. Only the real-binary fixtures above are evidence about Symposium behavior. Five snapshot files cover serialized eval outcomes; the JavaScript Claude stand-in and six transcript fixtures are inputs or drivers for inventoried tests rather than additional cases.
